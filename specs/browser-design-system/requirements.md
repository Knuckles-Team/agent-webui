# WEBUI-DESIGN requirements

| ID | Requirement | Verification |
|---|---|---|
| `WEBUI-DESIGN-R001` | **Design guidance distilled into component system and skills.** agent-webui distills license-reviewed accessibility, responsive, interaction and visual guidance from outside sources into the `src/components/ui/` primitives, the `src/index.css` tokens, and the public universal design and accessibility skills, ranking keyboard and screen-reader failures highest in its review rubric. The assimilation never installs duplicate skill names or copies unlicensed skill text. It adds no remote critique service or new telemetry. | Source diff and dependency audit confirm no duplicate skill names, unlicensed text, or new telemetry were introduced. |
| `WEBUI-DESIGN-R002` | **Design tokens documented with contrast targets.** The component system documents semantic color, typography, spacing, focus, density and state tokens sourced from `src/index.css`, including light and dark contrast targets for each. | Token audit and snapshot tests confirm documented tokens match `src/index.css` and meet the stated contrast targets. |
| `WEBUI-DESIGN-R003` | **Controls have accessible names and visible focus.** Every interactive control exposes an accessible name and a visible focus indicator, repeated filter rows label each individual clause distinctly, and dialogs trap keyboard focus while open and restore it to the triggering element on close. | Keyboard end-to-end tests cover the chat, Atlas and an operational form flow. |
| `WEBUI-DESIGN-R004` | **Responsive layout covers 320px mobile through desktop.** Layout patterns render correctly from 320px mobile width through desktop without horizontal overflow and without hiding any required action behind an unreachable control. | Viewport matrix tests with screenshot diffing across the mobile-to-desktop range. |
| `WEBUI-DESIGN-R005` | **Gesture actions have alternatives and respect reduced motion.** Every gesture-driven action also has a click or keyboard alternative, and when `prefers-reduced-motion` is set, nonessential animation is disabled while status feedback remains visible. | Touch-alternative and reduced-motion end-to-end tests. |
| `WEBUI-DESIGN-R006` | **Status states are distinguishable by text, not only color.** Loading, empty, stale, denied, error, success and pending states each render with distinct text in addition to color, and a long-running operation can be interrupted where doing so is safe. | Rendered tests against fixtures for each named state. |
| `WEBUI-DESIGN-R007` | **No duplicate primitives or unsolicited telemetry introduced.** No new component duplicates an existing UI primitive, no unsolicited telemetry is added, and any idea drawn from a third-party source is paraphrased in original wording only after its license has been reviewed and cleared. | Source diff and dependency audit confirm no duplicate primitives, no new telemetry, and license clearance for paraphrased content. |
| `WEBUI-DESIGN-R008` | **Fonts load from the same origin.** The interface ships its Inter font files inside the build and declares them with `@font-face` and a system fallback stack. The stylesheet imports no remote font or stylesheet. | A browser probe under the served policy records no `font-src` or `style-src-elem` violation for a remote URL. |
| `WEBUI-DESIGN-R009` | **Runtime style elements satisfy the strict policy.** The server issues a fresh nonce for each HTML document and adds it to `style-src` and `style-src-elem`. Each library that inserts a `<style>` element at runtime carries that nonce or ships its rules as a bundled stylesheet. The policy never gains `'unsafe-inline'` for style elements. | Server tests prove a fresh nonce per document. A browser probe under the served policy records no inline `style-src-elem` violation. |
| `WEBUI-DESIGN-R002.1` | **Purposeful density and Arbora visual hierarchy.** Use shared semantic spacing/type/color/state tokens and compact context navigation. Provide a primary working surface and optional related inspector/run tray. Wide views add useful panes rather than stretched prose; narrow views reflow to focused panes with persistent context. Tree/branch styling conveys relationship or navigation, not decoration. Never shrink text to fit or clip content to minimize scrolling. | Partial delivery: container-width pane composition in Work, Explore and Operate; native context disclosures retain mounted state. `e2e/workspace-density.spec.ts` exercises keyboard disclosure, draft retention and the viewport matrix. Screenshot/task-completion and full acceptance review remain open. |
| `WEBUI-DESIGN-R004.1` | **Full mobile and arbitrary-aspect feature parity.** Every route and action, including the currently mobile-unsupported cohort, remains available at all supported viewport sizes. Reflow tables, editors, charts, workflows and administration into usable focused views instead of hiding controls or forcing a desktop-only gate. No viewport/device category reduces authorization or feature coverage. Wide data may use an explicitly labelled scrollable region with keyboard access, not whole-page horizontal overflow. | Planned: All-route/action coverage at 320 CSS px, narrow/tall, low-height landscape, 4:3,16:9,32:9 and generated intermediate dimensions; no unsupported/mobile-only omission. |
| `WEBUI-DESIGN-R004.2` | **Resize, fold and visual viewport continuity.** Preserve selection, navigation history, unsent input, safe drafts, task progress and focus context. Cover resize, orientation, fold/unfold and on-screen keyboard changes. Respect safe areas and visual viewport; do not assume named device resolutions or fixed aspect ratios. Browser zoom to 200 percent preserves readable content and reachable actions. | Partial delivery: retained workspace viewport sizing and deferred focus reveal. Query journeys cover editing, pending responses and result inspection across native resize and simulated keyboard occlusion. A native 200-percent Chromium query journey checks keyboard access and retained edits. Full fold, native keyboard, browser zoom, stream and graph acceptance remain open. |
| `WEBUI-DESIGN-R005.1` | **Accessible interruptible semantic zoom.** Semantic zoom reveals readable native DOM surfaces, not merely scaled screenshots or tiny text. Map/list, breadcrumbs, search and explicit controls offer equivalent non-gesture access to every leaf. Transitions are interruptible and preserve focus; reduced motion removes camera travel while retaining state feedback. Touch/coarse targets are at least 44 CSS px unless an existing stricter requirement applies. | Partial delivery: loaded workspace branch browsing uses native DOM, explicit controls and breadcrumbs without camera travel. Rendered and Chromium journeys cover branch/search equivalence, focus, immediate ancestor return and resized layouts. Full deepest-leaf, touch and manual screen-reader acceptance remain open. |
| `WEBUI-DESIGN-R010` | **Measured performance under representative load.** Declare reference device/browser, network, fixture cardinality, capture method and budgets before acceptance. Representative journeys target p75 INP at most 200 ms, LCP at most 2.5 s and CLS at most 0.1. Target p95 local feedback at most 100 ms. Target p95 animation frames at most 16.7 ms on the declared 60 Hz reference. Virtualize/cull large data, retain worker/LOD seams, cancel obsolete work and bound streams/caches. No idle continuous animation or unsolicited telemetry. Report unsupported measurement cases and failures rather than claim zero lag. | Planned: Reproducible load/interaction traces, memory/idle checks and budget assertions plus reduced-motion tests on the exact release candidate. |

| `WEBUI-DESIGN-R011` | **Repeatable documentation screenshots.** Capture the real Work, Explore and Operate interfaces with deterministic synthetic responses at narrow and wide sizes. Block live services and private sessions. Provide refresh, artifact import and integrity checks with stable documentation paths and source/viewport/theme/fixture provenance. Persist actual PNG files for local use and read-only CI artifacts. Require complete successful captures and pixel review before committing the images. Capture output must not claim provider, accessibility or broader design acceptance. | Source: `scripts/documentation-screenshots.test.mjs` and `e2e/documentation-screenshots.browser.ts`. Acceptance: successful hosted captures, reviewed pixels, current README/docs assets, matching manifest and green CI. Source-only delivery remains SPECIFIED. |
