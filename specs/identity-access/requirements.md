# WEBUI-IDENTITY requirements

| ID | Requirement | Verification |
|---|---|---|
| `WEBUI-IDENTITY-R003` | **Identity mode wizard shows the active auth mode with no hidden bypass.** The identity wizard shows the operator-selected mode: explicit no-auth, built-in EG authentication or external OIDC (including Keycloak/Okta). Loopback bootstrap is a separate setup state, not an implicit authentication mode. It also shows a diagnostic check result. An explicitly configured no-auth mode is visible and policy-bounded. Missing credentials, broken verifiers and provider outages cannot select it implicitly. | Mode-specific rendered and server tests confirm each mode displays correctly and no bypass is possible. |
| `WEBUI-IDENTITY-R004` | **Local account flows use server sessions with no stored credentials.** Agent-webui's local registration, login, logout, forgot-password, reset-password and change-password flows use server-managed sessions with anti-CSRF protection. No credential or bearer token is stored in browser persistence. | End-to-end session-fixation and CSRF probe tests confirm no credential leaks into browser storage. |
| `WEBUI-IDENTITY-R005` | **MFA enrollment and recovery cover TOTP and WebAuthn.** Agent-webui supports MFA enrollment, challenge and recovery for both TOTP and WebAuthn, including recovery codes that can each be used only once. | Positive, replay and lost-device tests confirm enrollment, challenge and one-time recovery behavior. |
| `WEBUI-IDENTITY-R006` | **Identity admin tabs cover users, roles, groups and mapping dry run.** Agent-webui's administration interface provides tabs for users, roles, groups, authentication modes and a mapping-rule dry run, each calling a typed identity Arbora operation. | Authorized and denied generated-client tests confirm each admin tab enforces the correct access. |
| `WEBUI-IDENTITY-R007` | **Elevation requests display scope, expiry and a bound receipt.** Agent-webui's elevation request, approval and revocation views display the requested scope, reason, expiry and resulting receipt. The confirmation and step-up for an elevation action are bound to the caller and action that requested it. | Parity tests across chat and UI surfaces plus adversarial tests confirm the binding holds. |
| `WEBUI-IDENTITY-R008` | **Identity or tenant change invalidates cached protected data.** Changing the identity mode, tenant or session in agent-webui invalidates any cached protected data. It closes active privileged interactions. It does not leave them reachable under the prior context. | A two-principal browser test confirms cached data and privileged interactions are closed on change. |
| `WEBUI-IDENTITY-R009` | **Identity forms and confirmations are accessible on desktop and mobile.** Agent-webui's identity forms, error messages, admin tab panels and modal confirmations are usable by keyboard and screen reader, with equivalent behavior on mobile. | An accessibility end-to-end test suite confirms keyboard, screen-reader and mobile parity. |
| `WEBUI-IDENTITY-R001` | **Release-qualification identity test client supports a live sign-in probe.** Agent-webui's release qualification maintains a dedicated OIDC test client and test-realm user. A real browser sign-in probe against the identity provider can then run end to end. | A browser sign-in probe against the provisioned test client and user confirms the authentication path works. |
| `WEBUI-IDENTITY-R002` | **Admin UI surfaces identity operations for users, roles and navigation.** UserManagementView.tsx, AdminView.tsx and nav-registry.ts present identity administration through the Arbora identity API. | Authorized and denied generated-client tests against the live identity API confirm the admin UI enforces correct access. |
| `WEBUI-IDENTITY-R003.1` | **Explicit no-auth mode with bounded anonymous policy.** The operator can intentionally select no-auth for WebUI and its Arbora/EG composition. The UI clearly displays anonymous operation, its configured policy scope and the lack of confirmed human identity. Normal navigation and operations permitted by that policy work through the same UI/WebMCP dispatch. No synthetic logged-in principal, service bearer or no-op admission callback may masquerade as authentication. Network exposure obeys explicit host/origin policy; default qualification is isolated loopback. Anonymous provenance is distinguished from authenticated receipts. Operations requiring real identity, MFA, named approval or attended authenticated control must return a typed requirement/refusal, never fabricated proof. | Planned: The installed no-auth stack completes declared anonymous-policy journeys. It rejects out-of-scope/identity-required operations, cross-origin requests and accidental public exposure. UI/tool results identify the same anonymous scope. |
| `WEBUI-IDENTITY-R003.2` | **Built-in EG authentication through Arbora.** Provide built-in EG account/session authentication via Arbora-owned served identity operations and the existing WebUI session boundary. Login, session descriptors, authority and logout are composed from the real producer; WebUI stores no graph credentials or policy database. Browser HTTP and WebSocket requests carry the same validated context. | Planned: Test real composed EG login/session/use/logout with valid, invalid, expired, revoked and wrong-tenant sessions. Check HTTP/WebSocket parity and token protection. |
| `WEBUI-IDENTITY-R003.3` | **External OIDC provider interoperability.** Support configured Keycloak and Okta through the shared OIDC/session contract, validating issuer, audience, callback/state/nonce, verifier and tenant/role mapping. Provider secrets remain server-side. Partial configuration and unavailable or invalid providers fail closed without falling back to EG or no-auth. Treat provider selection/configuration changes as operator-controlled changes, not an unauthenticated browser toggle. | Planned: Test OIDC protocol fixtures and each claimed live provider. Reject wrong issuer/audience/state, replay, unavailable discovery/JWKS and incomplete configuration. Unavailable live-provider evidence remains explicit. |
| `WEBUI-IDENTITY-R010` | **Long-session renewal and mode-transition coherence.** Auth modes share one server-authoritative lifecycle for expiry, bounded renewal, logout, revocation, tenant change and cancellation. In-flight UI and WebMCP calls use current admitted context, never old privileged state after transition. Renewal does not extend a revoked or logged-out session; concurrent requests coordinate renewal rather than multiplying credentials. Expired sessions require reauthentication without losing safe unsent drafts. No-auth has no invented auth renewal; changing into or out of it retires prior caches, streams, tools and receipts. | Planned: Test long-running HTTP/stream/WebSocket and manual/WebMCP flows across renewal, expiry, revocation/logout, multiple tabs and mode changes. Reject privilege carryover, duplicate effects and hidden downgrade. |

| `WEBUI-IDENTITY-R003.1.1` | **Explicit anonymous source refusal boundary.** Explicit no-auth binds no authenticated identity or grant. Default-empty exact read policy cannot admit direct enhanced effects. Presented credentials, unsafe exposure and cross-origin actions refuse. | Source mode tests cover anonymous provenance, policy refusal and ambient-authority cleanup. This does not deliver full no-auth journeys. |
| `WEBUI-IDENTITY-R003.1.2` | **Complete installed anonymous journeys.** Complete the parent no-auth navigation, visible policy and governed operations through shared UI/WebMCP dispatch. Preserve containment, confirmation and truthful anonymous receipts. | Installed positive and adversarial anonymous-policy journeys and native effect qualification remain required. |
| `WEBUI-IDENTITY-R003.2.1` | **EG boundary configuration source refusal.** EG mode requires a typed host-owned EG session boundary. An arbitrary callback or absent owner refuses. No configuration failure changes the mode. | Source factory tests reject missing and untyped EG callbacks without provisioning credentials. |
| `WEBUI-IDENTITY-R003.2.2` | **Installed EG identity journeys.** Complete the parent real EG account, login, session, logout and HTTP/WebSocket context contract through Arbora. | Installed real producer/browser qualification remains required; source configuration refusal is not login support. |
| `WEBUI-IDENTITY-R003.3.1` | **OIDC configuration source refusal.** OIDC mode requires complete verifier and browser SSO configuration. It rejects an EG boundary and never silently changes provider mode. | Source factory tests reject incompatible owners and incomplete browser OIDC configuration. |
| `WEBUI-IDENTITY-R003.3.2` | **External provider interoperability qualification.** Complete the parent OIDC contract for configured Keycloak and Okta. Validate real provider journeys and all protocol refusal cases. | Protocol fixtures and each claimed live provider remain required; configuration tests do not qualify provider interoperability. |
