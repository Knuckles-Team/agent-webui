# WEBUI-IDENTITY-001 requirements

| ID | Requirement | Verification |
|---|---|---|
| `IDUI-01` | **Identity mode wizard shows the active auth mode with no hidden bypass.** Agent-webui's identity mode wizard displays whether OIDC, local authentication or loopback bootstrap is configured along with a diagnostic check result, and no mode can silently bypass authentication. | Mode-specific rendered and server tests confirm each mode displays correctly and no bypass is possible. |
| `IDUI-02` | **Local account flows use server sessions with no stored credentials.** Agent-webui's local registration, login, logout, forgot-password, reset-password and change-password flows use server-managed sessions with anti-CSRF protection, and no credential or bearer token is stored in browser persistence. | End-to-end session-fixation and CSRF probe tests confirm no credential leaks into browser storage. |
| `IDUI-03` | **MFA enrollment and recovery cover TOTP and WebAuthn.** Agent-webui supports MFA enrollment, challenge and recovery for both TOTP and WebAuthn, including recovery codes that can each be used only once. | Positive, replay and lost-device tests confirm enrollment, challenge and one-time recovery behavior. |
| `IDUI-04` | **Identity admin tabs cover users, roles, groups and mapping dry run.** Agent-webui's administration interface provides tabs for users, roles, groups, authentication modes and a mapping-rule dry run, each calling a typed identity Graph OS operation. | Authorized and denied generated-client tests confirm each admin tab enforces the correct access. |
| `IDUI-05` | **Elevation requests display scope, expiry and a bound receipt.** Agent-webui's elevation request, approval and revocation views display the requested scope, reason, expiry and resulting receipt, and the confirmation and step-up for an elevation action are bound to the same caller and action that requested it. | Parity tests across chat and UI surfaces plus adversarial tests confirm the binding holds. |
| `IDUI-06` | **Identity or tenant change invalidates cached protected data.** Changing the identity mode, tenant or session in agent-webui invalidates any cached protected data and closes active privileged interactions rather than leaving them reachable under the prior context. | A two-principal browser test confirms cached data and privileged interactions are closed on change. |
| `IDUI-07` | **Identity forms and confirmations are accessible on desktop and mobile.** Agent-webui's identity forms, error messages, admin tab panels and modal confirmations are usable by keyboard and screen reader, with equivalent behavior on mobile. | An accessibility end-to-end test suite confirms keyboard, screen-reader and mobile parity. |
| `WEBUI-IDENTITY-R001` | **Release-qualification identity test client supports a live sign-in probe.** Agent-webui's release qualification maintains a dedicated OIDC test client and test-realm user so that a real browser sign-in probe against the identity provider can run end to end. | A browser sign-in probe against the provisioned test client and user confirms the authentication path works. |
| `WEBUI-IDENTITY-R002` | **Admin UI surfaces identity operations for users, roles and navigation.** Agent-webui's UserManagementView.tsx, AdminView.tsx and nav-registry.ts implement the browser side of the identity administration operations against the Graph OS identity API. | Authorized and denied generated-client tests against the live identity API confirm the admin UI enforces correct access. |
