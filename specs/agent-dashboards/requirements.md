# OVERSTORY-DASH requirements

| ID | Requirement | Verification |
|---|---|---|
| `OVERSTORY-DASH-R001` | **Dashboard document model.** A dashboard is a declarative document with schema_version, id, title, revision, params and a grid of panels. Every edit raises the revision by 1. A 12-column grid bounds each panel. | `model.test.ts` passes. |
| `OVERSTORY-DASH-R002` | **Table, line, bar and KPI panels.** A panel is a query plus one visualization. The browser renders table, line, bar and KPI panels from a row set. Each panel shows loading, empty, error and unavailable states. | `DashboardsView.test.tsx` passes. |
| `OVERSTORY-DASH-R003` | **Pie, map and graph panels (remaining).** The panel kinds pie, map and graph render from a row set. The map reads latitude and longitude columns. The graph reads source and target columns. | `PanelKinds.test.tsx` passes. |
| `OVERSTORY-DASH-R004` | **UQL panel queries through arbora.** A panel query of kind uql runs through the same governed graph query route as Understory. The browser never contacts a data source directly. Unsafe query text is refused before sending. | `query.test.ts` passes. |
| `OVERSTORY-DASH-R005` | **Natural-language, fleet.call and EG panel queries (remaining).** Panel query kinds nl, fleet-call and eg-op run through arbora served operations. Those are eg.query.NlQuery, fleet.call and named eg.query operations. Each kind validates its arguments. | `query-kinds.test.ts` passes. |
| `OVERSTORY-DASH-R006` | **Hand-built dashboards.** A user creates a dashboard, adds, edits, moves and removes panels, and renames the dashboard in the UI. Every control works with the keyboard alone. | `DashboardsView.test.tsx` passes. |
| `OVERSTORY-DASH-R007` | **WebMCP dashboard tools.** The Overstory Studio page registers seven WebMCP tools. The tools are create, add_panel, update_panel, remove_panel, set_layout, list_data_sources and preview_query. Each tool validates input and output against a strict schema. Results stay under 1,500 bytes. | `tools.test.ts` passes. |
| `OVERSTORY-DASH-R008` | **Visible and undoable agent edits.** Each agent edit appears in an activity log tagged agent. A user undoes and redoes any edit, agent or user, with the keyboard. | `history.test.ts` passes. |
| `OVERSTORY-DASH-R009` | **Confirmed destructive agent changes.** An agent call that removes a panel waits for explicit user approval in the page. Denial, timeout or cancellation leaves the dashboard unchanged. | `tools.test.ts` passes. |
| `OVERSTORY-DASH-R010` | **Save through arbora as catalog assets (remaining).** The browser saves, loads, lists, drops and shares dashboards through the arbora dashboard operations (ARBORA-OPS-R861). EG stores each dashboard as the catalog asset of MEDULLA-TYPED-PACKS-R108, with an owner. A stale revision yields a conflict, never an overwrite. | `store-arbora.test.ts` passes. |
| `OVERSTORY-DASH-R011` | **Local fallback marked pending.** Until R010 lands, the browser keeps dashboards in local storage. The page states that the save is local and pending. Storage failure leaves the in-memory dashboard intact and says so. | `store.test.ts` passes. |
| `OVERSTORY-DASH-R012` | **Ownership and sharing (remaining).** The page shows the owner and the caller's access level. An owner grants or revokes reader or editor access. A reader sees no edit controls and the edit tools refuse. | `ShareDialog.test.tsx` passes. |
| `OVERSTORY-DASH-R013` | **Refresh, parameters and filters.** A refresh control reruns every panel query. An optional interval refreshes on a timer. Dashboard parameters substitute into queries as validated typed values, and a change reruns the affected panels. | `params.test.ts` passes. |
| `OVERSTORY-DASH-R014` | **Accessible and themed panels.** Every panel has a text summary and a data table alternative. Series differ by more than color. Panels follow the light and dark theme tokens and respect reduced motion. | `DashboardsView.test.tsx` passes. |
| `OVERSTORY-DASH-R015` | **Dashboards route wiring.** The route workspace.dashboards in the navigation registry mounts the view. The view mounts the WebMCP registrar, so the tools exist only on that page. | `DashboardsView.test.tsx` passes. |
| `OVERSTORY-DASH-R016` | **Catalog browse and search page (remaining).** The Catalog page lets a user browse and search the EG metadata catalog through arbora. It lists connector assets, glossary terms, lineage, owners, ratings, comments, Agent Library entries, workflows, knowledge graphs and dashboards. Related: MEDULLA-TYPED-PACKS-R106, MEDULLA-TYPED-PACKS-R108 and the arbora catalog operations. | `CatalogPage.test.tsx` passes. |
