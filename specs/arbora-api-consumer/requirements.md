# OVERSTORY-API requirements

| ID | Requirement | Verification |
|---|---|---|
| `OVERSTORY-API-R001` | **Generated Arbora API client with typed decisions and confirmation flows.** Agent-webui generates a versioned TypeScript client and a single invoke adapter from the Arbora API schema. It migrates decisions, Markets/apps pages and WebMCP tools to call the client. The console confirmation page sends only the exact server-issued plan reference. That reference completes a previewed effect. | Contract tests against the generated client plus positive and negative effect tests on the confirmation flow verify this. |
| `OVERSTORY-API-R002` | **Typed ontology, graph, Atlas and object-set operations replace host routes.** Generated Arbora operations replace the ontology, graph, Atlas and object-set route blocks in agent-webui's api_extensions.py. They also replace the corresponding src callers. The operations preserve tenant scoping, purpose context, cursor pagination and existing error semantics. | Cross-surface fixture tests and browser tests covering each migrated route family confirm parity with the prior behavior. |
| `OVERSTORY-API-R003` | **Remaining domain routes migrate to generated operations with a route census (rollup).** Split into `OVERSTORY-API-R003.1` (route-census typed model) and `OVERSTORY-API-R003.2` (route-census data file and lint rule), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `OVERSTORY-API-R003.1` | **Route-census typed model.** A typed `RouteCensusEntry` model with a strict disposition enum records each route's owning operation. It refuses a `generated-operation` row that omits its owning operation. | Verified by `route-census.test.ts` asserting the refusal and disposition-enum behavior. |
| `OVERSTORY-API-R003.2` | **Route-census data file and lint rule (remaining).** The remaining scope has two parts. One is a checked-in route census data file populated for every `api_extensions.py` domain route family. The other is an architecture lint rule that runs in CI and rejects any new unclassified domain route. | Route-census and contract tests plus the lint rule running in continuous integration confirm no unclassified domain route remains. |
| `OVERSTORY-API-R004` | **Each request carries its own correlation id.** The host mints a fresh correlation id for each HTTP request and WebSocket connection without an inbound `x-correlation-id`. An ambient id bound on the serving thread never enters a request. | An observability test binds an ambient id and serves two requests. It confirms two distinct ids that differ from the ambient one. |
| `OVERSTORY-API-R006` | **Generated TypeScript client from a pinned Arbora schema.** Agent-webui generates its TypeScript types and client from a pinned Arbora v1 API schema and digest. The client exposes one invoke adapter and a stable error envelope for all callers. | A regeneration-diff check plus contract tests confirm the generated client matches the pinned schema and envelope. |
| `OVERSTORY-API-R007` | **Typed operations preserve preview-confirm-step-up for effects.** Decisions, Markets/apps pages, WebMCP tools and the console confirmation flow in agent-webui call typed Arbora operations through the generated client. They preserve the preview, confirmation and step-up sequence. That sequence is required before any side-effecting action runs. | Positive and negative effect tests exercise the preview, confirm and step-up sequence end to end. |
| `OVERSTORY-API-R008` | **Ontology, graph, Atlas and object-set operations preserve tenant semantics (rollup).** Split by code root into `OVERSTORY-API-R008.1` (ontology), `OVERSTORY-API-R008.2` (graph), `OVERSTORY-API-R008.3` (Atlas) and `OVERSTORY-API-R008.4` (object-set), producer first. This row is LANDED only when all four children are LANDED. | Each child's own verification row; see below. |
| `OVERSTORY-API-R008.1` | **Ontology reads and writes use typed Arbora operations with preserved tenant semantics.** Agent-webui's ontology callers call typed Arbora operations. The callers cover schema graph, catalogue, import/export, registry types and interfaces. They live in `agent/agent_webui/api_extensions.py` and their `src` counterparts. The operations preserve tenant scoping, purpose context, cursor pagination and existing error semantics. | Cross-surface fixtures and a browser test confirm ontology-read parity after migration. |
| `OVERSTORY-API-R008.2` | **Graph reads and writes use typed Arbora operations with preserved tenant semantics.** Agent-webui's graph callers in `agent/agent_webui/api_extensions.py` and their `src` counterparts call typed Arbora operations that preserve tenant scoping, purpose context, cursor pagination and existing error semantics. | Cross-surface fixtures and a browser test confirm graph-read/write parity after migration. |
| `OVERSTORY-API-R008.3` | **Atlas reads and writes use typed Arbora operations with preserved tenant semantics.** Agent-webui's Atlas callers in `agent/agent_webui/api_extensions.py` and their `src` counterparts call typed Arbora operations that preserve tenant scoping, purpose context, cursor pagination and existing error semantics. | Cross-surface fixtures and a browser test confirm Atlas parity after migration. |
| `OVERSTORY-API-R008.4` | **Object-set reads and writes use typed Arbora operations with preserved tenant semantics.** Agent-webui's object-set callers (`ObjectExplorerView`, `ObjectView`) in `agent/agent_webui/api_extensions.py` and their `src` counterparts call typed Arbora operations that preserve tenant scoping, purpose context, cursor pagination and existing error semantics. | Cross-surface fixtures and a browser test confirm object-set parity after migration. |
| `OVERSTORY-API-R009` | **Prompts, SDD, knowledge base, sessions and goals migrate to typed calls.** Agent-webui's prompts, SDD, knowledge base, sessions, goals, MCP servers/tools and model-management features call typed Arbora operations in place of host-owned routes. | A route census and contract tests confirm each family is covered by a generated operation. |
| `OVERSTORY-API-R010` | **Host drops direct internal imports once replacement operations are proven.** Agent-webui removes direct internal imports and domain route handlers from its host once the replacement Arbora operations are proven. It keeps only an explicitly inventoried set of browser-local endpoints. | A static dependency check and route-census gate confirm no forbidden import or unlisted domain route remains. |
| `OVERSTORY-API-R011` | **Shared auth and streaming are preserved without exposing a service bearer.** Agent-webui preserves shared authentication, credential delegation, streaming and cancel behavior, and error handling across the migration. It never exposes an Arbora service bearer token to browser JavaScript. | Host integration tests and adversarial browser tests confirm the bearer is never exposed and behavior is preserved. |
| `OVERSTORY-API-R005` | **Failure logs carry a sanitized typed error code.** `_log_failure` in api_extensions.py logs the operation label, exception type and an `error_code`. The code comes from the `engine_error_code` or `code` attribute. A value that is not an upper-case token of 64 characters or fewer is logged as `none`. Message text never reaches the log. | tests/test_log_failure_error_code.py confirms `ACCESS_DENIED` is logged, malformed codes log `none`, and message text is absent. |
| `OVERSTORY-API-R011.1` | **Host composition without an engine.** The WebUI factory holds no graph engine. A host composes its routes through `application_composer` on the real factory. Graph data comes only from Arbora served operations; a route without one answers 501 `not_available`. Injection grants no identity or session authority. | Host-seam tests prove the served-operation calls and the `not_available` answers through the real factory. |
| `OVERSTORY-API-R011.2` | **Chat preserves explicit conversation and admitted task identities.** The browser sends its selected conversation identity from the first turn. Its cache, draft and SDK state are scoped to the observed caller and tenant. The host does not derive identity from prompt text. It rejects conflicting conversation identities and propagates only explicit Arbora task, context, run and trace references through message metadata. A trace reference is not interpreted as a graph trace ID. | Mounted chat transport and host streaming tests prove first-turn identity, conversation isolation, missing and conflicting identity, and exact returned references. This does not establish durable resume or trace retrieval. |

| `OVERSTORY-API-R011.2.1` | **Conversation and admitted-identity source preservation.** Bind selected conversation identity in mounted transport source. Scope cache, draft and SDK state to the observed caller and tenant. Reject conflicting conversation identities. Preserve only explicit returned task, context, run and trace references in host message metadata. Do not derive identity from prompt text or treat a trace reference as a graph trace ID. | Source fixtures cover first-turn identity, isolation, malformed and conflicting identity, and exact returned references. These fixtures do not qualify the installed composed browser-to-Arbora path. |
| `OVERSTORY-API-R011.2.2` | **Composed conversation identity qualification.** Retain every parent R011.2 obligation beyond source fixture coverage. Qualify the mounted browser transport and host streaming path against the installed Arbora provider. | Planned: Prove first-turn identity, observed caller and tenant isolation, missing and conflicting identity, and exact returned references through the composed path. Keep durable resume and trace retrieval separate. |

## Public execution projection

| ID | Requirement | Verification |
|---|---|---|
| `OVERSTORY-API-R011.3` | **Adapt the shared public execution contract.** Extend `orchestrator_model.py` and the existing browser client through registered Arbora operations. Preserve explicit node, owner, root-task, run and context bindings. Project only authorized public summaries, tool activity and transcript parts. Preserve snapshot/cursor semantics and default-false control capabilities. Preserve replay-v1 decoding; negotiate new projections separately. Do not infer child targets or expose service credentials. Depends-on: ARBORA-OPS-R021.4.8, ARBORA-OPS-R021.4.9. | Planned `test_execution_projection.py::test_public_execution_adapter` and `execution-projection.test.ts::binding_and_refusal` cover schema compatibility, exact identity, ordered replay, redaction and denial. Installed-producer qualification remains required. |
