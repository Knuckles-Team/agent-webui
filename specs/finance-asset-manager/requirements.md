# FIN-UI requirements

| ID | Requirement | Verification |
|---|---|---|
| `FIN-UI-R001` | **Mobile-first Markets app with five-destination navigation (rollup).** Split into `FIN-UI-R001.1` (detail-tab support) and `FIN-UI-R001.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FIN-UI-R001.1` | **Detail-tab support model.** A typed detail-tab support model decides which of the six detail tabs an instrument supports. The tabs are Chart, Rates, News, Notes, Dividends and Analysis. The instrument's series capabilities set the result. | Verified by `detail-support.test.ts` asserting each capability combination yields the correct supported/unsupported tab set. |
| `FIN-UI-R001.2` | **Live Markets app wiring (remaining).** The remaining scope is wiring these parts into the live Markets app. The parts are the five-destination navigation, instrument groups and sparkline rows. They also include the detail view's six tabs gated by `FIN-UI-R001.1`. The range selector and the performance-versus-benchmark card complete the list. The wiring includes PWA install, theming and accessibility. | Verified by a responsive browser test across phone and desktop viewports confirming the navigation, group and detail views, and accessibility behavior. |
| `FIN-UI-R002` | **Shared ChartRenderer for line, candle, and overlay data (rollup).** Split into `FIN-UI-R002.1` (ChartRenderer contract) and `FIN-UI-R002.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FIN-UI-R002.1` | **Shared ChartRenderer input contract.** A typed shared ChartRenderer input contract validates line series and complete OHLC candle series. It defines decimation that never alters finalized trail, flip or state output. It also defines a versioned, simulation-flagged overlay marker type. | Verified by `chart-contract.test.ts` asserting decimated and full-resolution views of the same fixture produce identical finalized trend and overlay output. |
| `FIN-UI-R002.2` | **Live ChartRenderer wiring (remaining).** The remaining scope is wiring the shared ChartRenderer contract into the live ChartRenderer and ChartPage components. The components render line, area and candle series with a volume pane. They draw overlays. The overlays cover trend lines, flips, DCA buys, cost basis, and margin and liquidation levels. They support touch crosshair and pinch-zoom interaction. | Verified by a chart-rendering test comparing full-resolution and decimated views of the same fixture and asserting identical finalized trend and overlay output. |
| `FIN-UI-R004` | **Responsive five-destination navigation.** The application presents five top-level destinations. On narrow viewports they appear as a bottom navigation bar. On desktop they appear as a side rail. The selected route and keyboard focus stay coherent across layouts. | Verified by a responsive browser test at phone and desktop widths confirming the correct navigation chrome and consistent selection and focus. |
| `FIN-UI-R005` | **Instrument groups with distinct data states.** User-defined instrument groups and their Basic/Holdings mode preserve the selected group and mode. The UI shows each of these results as a separate state: loading, genuinely empty, stale, partial, permission-denied and unavailable. It never collapses them into one state. | Verified by a component test driving each data state from a fixture and asserting a distinct, correctly labeled rendering for each. |
| `FIN-UI-R006` | **Search resolves by stable identity, not ticker text.** Instrument search and selection key off stable instrument and listing IDs, together with venue and quote currency. A ticker symbol alone never identifies an instrument. | Verified by a test using two identically ticked instruments on different venues and asserting search and detail views keep them distinct by ID. |
| `FIN-UI-R007` | **Instrument rows show price, provenance, after-hours value.** Instrument rows and detail views show the current price with session and source provenance. They also show the previous close, the price change and a sparkline. They show a licensed logo or text fallback. When the owner supplies an after-hours value, they label it separately. | Verified by a fixture-driven test covering regular, pre-market, post-market, delayed, and missing quotes, asserting each field renders correctly and a missing price is never shown as zero. |
| `FIN-UI-R008` | **Detail tabs and range controls expose only supported data (rollup).** Split into `FIN-UI-R008.1` (supportedChartMode) and `FIN-UI-R008.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FIN-UI-R008.1` | **Pure supportedChartMode gating function.** A pure `supportedChartMode` function gates interval, data-type and volume combinations for the detail view. It returns an explanatory reason when a combination is unsupported. | Verified by `chart-contract.test.ts` and `detail-support.test.ts` driving valid and unsupported timeframe/data-type combinations and asserting the correct supported state and reason. |
| `FIN-UI-R008.2` | **Live detail-tab/range-control wiring (remaining).** The remaining scope is wiring `supportedChartMode` into the live detail view's tabs, range controls and line, candle and volume toggle. The running UI then hides or explains unsupported options. Fixtures alone do not meet this need. | Verified by a test driving valid and unsupported timeframe and data-type combinations and asserting unsupported options are hidden or explained rather than silently rendered. |
| `FIN-UI-R009` | **Shared ChartRenderer preserves gaps and revisions.** One typed ChartRenderer, shared with the Atlas renderer, draws scalar line and area series and complete OHLC candles. It preserves data gaps. It preserves bar revisions by ID. It does not smooth over them. It performs no authoritative indicator computation of its own. | Verified by a unit and browser test asserting candle mode only accepts valid OHLC bars, gaps persist, a revised bar replaces the prior one by ID, and no indicator values originate client-side. |
| `FIN-UI-R010` | **Chart overlays show strategy version and simulation state (rollup).** Split into `FIN-UI-R010.1` (overlay marker type) and `FIN-UI-R010.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FIN-UI-R010.1` | **Overlay marker version/simulation-flag type.** Chart overlay markers carry a strategy version. They also carry a simulation flag. `overlayLabel` tags simulated results apart from finalized ones. | Verified by the batch-2 contract tests asserting overlay markers carry the correct version and simulation label for a finalized trend flip, DCA buy, cost basis, and simulated margin level. |
| `FIN-UI-R010.2` | **Live chart overlay wiring (remaining).** The remaining scope is wiring the versioned overlay marker type into the live chart overlay rendering. The marker type carries a simulation flag. The overlays cover trend lines, flips, DCA buys, cost basis, and margin and liquidation levels. | Verified by a test comparing full-resolution and decimated chart views on a fixture with a finalized trend flip, DCA buy, cost basis, and simulated margin level, asserting markers align to the correct bars and versions. |
| `FIN-UI-R011` | **Performance cards render owner-calculated values verbatim (rollup).** Split into `FIN-UI-R011.1` (verbatim-value contract) and `FIN-UI-R011.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FIN-UI-R011.1` | **Performance/benchmark card verbatim-value contract.** Performance and benchmark cards reproduce the owning service's decimal string verbatim. They have explicit unavailable and stale states. They never recompute values on the client. | Verified by the batch-2 contract-fixture tests with multi-currency cash flows, dividends, splits, fees, and a stale valuation, asserting no client-side recomputation. |
| `FIN-UI-R011.2` | **Live performance/benchmark card wiring (remaining).** The remaining scope is wiring the verbatim-value contract into the live performance and benchmark card components. The cards show the return method and currency. They also show the source, as-of time and session. | Verified by a contract-fixture test with multi-currency cash flows, dividends, splits, fees, and a stale valuation, asserting the UI reproduces the owner's decimal-string output with no client-side recomputation. |
| `FIN-UI-R012` | **Strategy views cite evidence and never submit orders (rollup).** Split into `FIN-UI-R012.1` (evidence/abstain contract) and `FIN-UI-R012.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FIN-UI-R012.1` | **Strategy view evidence/abstain contract type.** Strategy recommendation view types cite versioned evidence or an explicit abstain reason, and contain no order-submission field by construction. | Verified by the batch-2 fixture tests covering a calibrated proposal, thin history, warmup, drift, and a missing scorecard. |
| `FIN-UI-R012.2` | **Live strategy/recommendation view wiring (remaining).** The remaining scope is wiring the evidence and abstain contract type into the live views. These are the strategy and recommendation views. No order-submission path exists in the rendered UI. | Verified by a fixture test covering a calibrated proposal, thin history, warmup, drift, and a missing scorecard, asserting the shown evidence and abstention reason and confirming no order request originates from the panel. |
| `FIN-UI-R013` | **DCA and alert views distinguish delivery states (rollup).** Split into `FIN-UI-R013.1` (delivery-receipt dedupe) and `FIN-UI-R013.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FIN-UI-R013.1` | **DCA/alert delivery-receipt dedupe contract.** DCA and alert delivery receipts dedupe a duplicated event ID. They also dedupe a channel retry. The UI never reports a paper fill as a live fill. | Verified by the batch-2 fixture tests exercising due, missed, failed, replayed, paper-filled, and delivered states including a duplicated event ID and channel retry. |
| `FIN-UI-R013.2` | **Live DCA/alert delivery-state wiring (remaining).** The remaining scope is wiring the delivery-receipt dedupe contract into the live DCA and alert views. Each state renders as a distinct outcome. | Verified by a fixture test exercising each state, including a duplicated event ID and a channel retry, asserting the states and receipts remain distinct and a paper fill is never shown as a live fill. |
| `FIN-UI-R014` | **CSV import preview with idempotent receipt (rollup).** Split into `FIN-UI-R014.1` (CSV import contract) and `FIN-UI-R014.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FIN-UI-R014.1` | **CSV import preview contract mirroring the SDK.** CSV import preview types mirror `agent_connector_sdk.finance.csv_import`, modeling column-mapping errors and idempotent re-import keyed by file digest. | Verified by the batch-3 CSV fixture tests with mapped and unmapped columns, a malformed row, and a duplicate digest. |
| `FIN-UI-R014.2` | **Live CSV import preview wiring (remaining).** The remaining scope is wiring the CSV import preview contract into the live import flow. After import, the flow shows holdings from the owning service's response. | Verified by a CSV fixture test with mapped and unmapped columns, a malformed row, and a duplicate digest, asserting preview counts, idempotent receipts, and owner-sourced holdings. |
| `FIN-UI-R015` | **Offline PWA shell marks cached data stale (rollup).** Split into `FIN-UI-R015.1` (offline cache contract) and `FIN-UI-R015.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FIN-UI-R015.1` | **Offline cache staleness contract.** An offline cache view type marks data stale and disables current-state actions while offline or expired. | Verified by the batch-3 offline-cache fixture tests. |
| `FIN-UI-R015.2` | **Live offline PWA shell wiring (remaining).** The remaining scope is wiring the offline cache staleness contract into the live installed PWA shell. Offline, the shell shows previously cached financial facts. It marks them stale. Current-data actions are disabled. | Verified by an offline test loading a previously valid finance view without network access and asserting cached values are labeled stale and current-data actions are unavailable. |
| `FIN-UI-R016` | **Charts and controls meet accessibility requirements (rollup).** Split into `FIN-UI-R016.1` (accessibility contract) and `FIN-UI-R016.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FIN-UI-R016.1` | **Chart accessibility text-summary contract.** A chart accessibility contract defines a screen-reader text summary and non-color direction words for chart state. | Verified by the batch-3 accessibility contract tests. |
| `FIN-UI-R016.2` | **Live chart/control accessibility wiring (remaining).** The remaining scope is wiring the accessibility text-summary contract into the live charts and controls. This covers keyboard operation and 200% zoom. It also covers reduced motion and non-color state indicators. | Verified by an accessibility review combining keyboard-only operation, screen-reader inspection, 200% zoom, reduced-motion, and high-contrast checks against each chart and control. |
| `FIN-UI-R003` | **Arbora Markets app with scanner, search, and layered chart.** An Arbora-hosted Markets application offers a market overview and a scanner with filters. It also offers symbol search and a layered chart view. It reuses the shared Atlas OHLC ChartRenderer and the epistemic-graph engine's large-dataset decimation. It also exposes its market actions as WebMCP tools. | Verified by an integration test driving the scanner, search, and chart views against fixture market data and confirming the WebMCP tool calls return the expected results. |
