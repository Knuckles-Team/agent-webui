# FIN-UI-001 requirements

| ID | Requirement | Verification |
|---|---|---|
| `FIN-UI-R001` | **Mobile-first Markets app with five-destination navigation (rollup).** Split into `FIN-UI-R001.1` (detail-tab support) and `FIN-UI-R001.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FIN-UI-R001.1` | **Detail-tab support model.** A typed detail-tab support model determines which of the six detail tabs (Chart, Rates, News, Notes, Dividends, Analysis) an instrument's series capabilities allow. | Verified by `detail-support.test.ts` asserting each capability combination yields the correct supported/unsupported tab set. |
| `FIN-UI-R001.2` | **Live Markets app wiring (remaining).** The remaining scope: wiring the five-destination navigation, instrument groups, sparkline rows, the detail view's six tabs gated by `FIN-UI-R001.1`, range selector, and performance-versus-benchmark card into the live Markets app, with PWA install, theming, and accessibility. | Verified by a responsive browser test across phone and desktop viewports confirming the navigation, group and detail views, and accessibility behavior. |
| `FIN-UI-R002` | **Shared ChartRenderer for line, candle, and overlay data (rollup).** Split into `FIN-UI-R002.1` (ChartRenderer contract) and `FIN-UI-R002.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FIN-UI-R002.1` | **Shared ChartRenderer input contract.** A typed shared ChartRenderer input contract validates line versus complete OHLC candle series, defines decimation that provably never alters finalized trail/flip/state output, and a versioned, simulation-flagged overlay marker type. | Verified by `chart-contract.test.ts` asserting decimated and full-resolution views of the same fixture produce identical finalized trend and overlay output. |
| `FIN-UI-R002.2` | **Live ChartRenderer wiring (remaining).** The remaining scope: wiring the shared ChartRenderer contract into the live ChartRenderer/ChartPage components — rendering line/area and candle series with a volume pane, drawing overlays for trend lines/flips, DCA buys, cost basis, and margin/liquidation levels, and touch crosshair/pinch-zoom interaction. | Verified by a chart-rendering test comparing full-resolution and decimated views of the same fixture and asserting identical finalized trend and overlay output. |
| `FUI-01` | **Responsive five-destination navigation.** The application presents five top-level destinations as a bottom navigation bar on narrow viewports and as a side rail on desktop, keeping the selected route and keyboard focus coherent across layouts. | Verified by a responsive browser test at phone and desktop widths confirming the correct navigation chrome and consistent selection and focus. |
| `FUI-02` | **Instrument groups with distinct data states.** User-defined instrument groups and their Basic/Holdings mode preserve the selected group and mode, and the UI visibly distinguishes loading, genuinely empty, stale, partial, permission-denied, and unavailable results rather than collapsing them into one state. | Verified by a component test driving each data state from a fixture and asserting a distinct, correctly labeled rendering for each. |
| `FUI-03` | **Search resolves by stable identity, not ticker text.** Instrument search and selection key off stable instrument and listing IDs together with venue and quote currency, so a ticker symbol alone never identifies or disambiguates an instrument. | Verified by a test using two identically ticked instruments on different venues and asserting search and detail views keep them distinct by ID. |
| `FUI-04` | **Instrument rows show price, provenance, after-hours value.** Instrument rows and detail views display the current price with session and source provenance, the previous close, price change, a sparkline, a licensed logo or text fallback, and a separately labeled after-hours value when one is supplied. | Verified by a fixture-driven test covering regular, pre-market, post-market, delayed, and missing quotes, asserting each field renders correctly and a missing price is never shown as zero. |
| `FUI-05` | **Detail tabs and range controls expose only supported data (rollup).** Split into `FUI-05.1` (supportedChartMode) and `FUI-05.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FUI-05.1` | **Pure supportedChartMode gating function.** A pure `supportedChartMode` function gates interval/data-type/volume combinations for the detail view, returning an explanatory reason when a combination is unsupported. | Verified by `chart-contract.test.ts` and `detail-support.test.ts` driving valid and unsupported timeframe/data-type combinations and asserting the correct supported state and reason. |
| `FUI-05.2` | **Live detail-tab/range-control wiring (remaining).** The remaining scope: wiring `supportedChartMode` into the live detail view's tabs, range controls, and line/candle/volume toggle so unsupported options are hidden or explained in the running UI rather than only in fixtures. | Verified by a test driving valid and unsupported timeframe and data-type combinations and asserting unsupported options are hidden or explained rather than silently rendered. |
| `FUI-06` | **Shared ChartRenderer preserves gaps and revisions.** One typed ChartRenderer, shared with the Atlas renderer, draws scalar line/area series and complete OHLC candles, preserves data gaps and bar revisions by ID rather than smoothing over them, and performs no authoritative indicator computation of its own. | Verified by a unit and browser test asserting candle mode only accepts valid OHLC bars, gaps persist, a revised bar replaces the prior one by ID, and no indicator values originate client-side. |
| `FUI-07` | **Chart overlays show strategy version and simulation state (rollup).** Split into `FUI-07.1` (overlay marker type) and `FUI-07.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FUI-07.1` | **Overlay marker version/simulation-flag type.** Chart overlay markers carry a strategy version and simulation flag; `overlayLabel` tags simulated results distinctly from finalized ones. | Verified by the batch-2 contract tests asserting overlay markers carry the correct version and simulation label for a finalized trend flip, DCA buy, cost basis, and simulated margin level. |
| `FUI-07.2` | **Live chart overlay wiring (remaining).** The remaining scope: wiring the versioned, simulation-flagged overlay marker type into the live chart overlay rendering for trend lines/flips, DCA buys, cost basis, and margin/liquidation levels. | Verified by a test comparing full-resolution and decimated chart views on a fixture with a finalized trend flip, DCA buy, cost basis, and simulated margin level, asserting markers align to the correct bars and versions. |
| `FUI-08` | **Performance cards render owner-calculated values verbatim (rollup).** Split into `FUI-08.1` (verbatim-value contract) and `FUI-08.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FUI-08.1` | **Performance/benchmark card verbatim-value contract.** Performance and benchmark cards reproduce the owning service's decimal string verbatim, with explicit unavailable and stale states, and no client-side recomputation. | Verified by the batch-2 contract-fixture tests with multi-currency cash flows, dividends, splits, fees, and a stale valuation, asserting no client-side recomputation. |
| `FUI-08.2` | **Live performance/benchmark card wiring (remaining).** The remaining scope: wiring the verbatim-value contract into the live performance and benchmark card components, including return method, currency, source, as-of time, and session display. | Verified by a contract-fixture test with multi-currency cash flows, dividends, splits, fees, and a stale valuation, asserting the UI reproduces the owner's decimal-string output with no client-side recomputation. |
| `FUI-09` | **Strategy views cite evidence and never submit orders (rollup).** Split into `FUI-09.1` (evidence/abstain contract) and `FUI-09.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FUI-09.1` | **Strategy view evidence/abstain contract type.** Strategy recommendation view types cite versioned evidence or an explicit abstain reason, and contain no order-submission field by construction. | Verified by the batch-2 fixture tests covering a calibrated proposal, thin history, warmup, drift, and a missing scorecard. |
| `FUI-09.2` | **Live strategy/recommendation view wiring (remaining).** The remaining scope: wiring the evidence/abstain contract type into the live strategy and recommendation views, confirming no order-submission path exists in the rendered UI. | Verified by a fixture test covering a calibrated proposal, thin history, warmup, drift, and a missing scorecard, asserting the shown evidence and abstention reason and confirming no order request originates from the panel. |
| `FUI-10` | **DCA and alert views distinguish delivery states (rollup).** Split into `FUI-10.1` (delivery-receipt dedupe) and `FUI-10.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FUI-10.1` | **DCA/alert delivery-receipt dedupe contract.** DCA and alert delivery receipts dedupe a duplicated event ID or channel retry; a paper fill is never reported as a live fill. | Verified by the batch-2 fixture tests exercising due, missed, failed, replayed, paper-filled, and delivered states including a duplicated event ID and channel retry. |
| `FUI-10.2` | **Live DCA/alert delivery-state wiring (remaining).** The remaining scope: wiring the delivery-receipt dedupe contract into the live DCA and alert views so each state renders as a visibly distinct outcome. | Verified by a fixture test exercising each state, including a duplicated event ID and a channel retry, asserting the states and receipts remain distinct and a paper fill is never shown as a live fill. |
| `FUI-11` | **CSV import preview with idempotent receipt (rollup).** Split into `FUI-11.1` (CSV import contract) and `FUI-11.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FUI-11.1` | **CSV import preview contract mirroring the SDK.** CSV import preview types mirror `agent_connector_sdk.finance.csv_import`, modeling column-mapping errors and idempotent re-import keyed by file digest. | Verified by the batch-3 CSV fixture tests with mapped and unmapped columns, a malformed row, and a duplicate digest. |
| `FUI-11.2` | **Live CSV import preview wiring (remaining).** The remaining scope: wiring the CSV import preview contract into the live import flow, including post-import holdings display from the owning service's response. | Verified by a CSV fixture test with mapped and unmapped columns, a malformed row, and a duplicate digest, asserting preview counts, idempotent receipts, and owner-sourced holdings. |
| `FUI-12` | **Offline PWA shell marks cached data stale (rollup).** Split into `FUI-12.1` (offline cache contract) and `FUI-12.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FUI-12.1` | **Offline cache staleness contract.** An offline cache view type marks data stale and disables current-state actions while offline or expired. | Verified by the batch-3 offline-cache fixture tests. |
| `FUI-12.2` | **Live offline PWA shell wiring (remaining).** The remaining scope: wiring the offline cache staleness contract into the live installed PWA shell so previously cached financial facts display while offline, marked stale, with current-data actions disabled. | Verified by an offline test loading a previously valid finance view without network access and asserting cached values are labeled stale and current-data actions are unavailable. |
| `FUI-13` | **Charts and controls meet accessibility requirements (rollup).** Split into `FUI-13.1` (accessibility contract) and `FUI-13.2` (live wiring), producer first. This row is LANDED only when both children are LANDED. | Each child's own verification row; see below. |
| `FUI-13.1` | **Chart accessibility text-summary contract.** A chart accessibility contract defines a screen-reader text summary and non-color direction words for chart state. | Verified by the batch-3 accessibility contract tests. |
| `FUI-13.2` | **Live chart/control accessibility wiring (remaining).** The remaining scope: wiring the accessibility text-summary contract into the live charts and controls — keyboard operation, 200% zoom, reduced-motion, and non-color state indicators. | Verified by an accessibility review combining keyboard-only operation, screen-reader inspection, 200% zoom, reduced-motion, and high-contrast checks against each chart and control. |
| `FIN-UI-R003` | **GraphOS Markets app with scanner, search, and layered chart.** A GraphOS-hosted Markets application provides a market overview, a scanner with filters, symbol search, and a layered chart view, reusing the shared Atlas OHLC ChartRenderer and the epistemic-graph engine's large-dataset decimation, and exposes its market actions as WebMCP tools. | Verified by an integration test driving the scanner, search, and chart views against fixture market data and confirming the WebMCP tool calls return the expected results. |
