# FIN-UI-001 requirements

| ID | Requirement | Verification |
|---|---|---|
| `FIN-UI-R001` | **Mobile-first Markets app with five-destination navigation.** The Markets app provides a mobile bottom navigation bar for Markets, News, Calendar, Portfolio, and Menu (a side rail on desktop), instrument groups with Basic and Holdings views, sparkline rows with change indicators and a post-market value, a detail view with Chart, Rates, News, Notes, Dividends, and Analysis tabs, a range selector, and a performance-versus-benchmark card; it installs as a PWA, supports dark and light themes, and is keyboard and screen-reader accessible. | Verified by a responsive browser test across phone and desktop viewports confirming the navigation, group and detail views, and accessibility behavior. |
| `FIN-UI-R002` | **Shared ChartRenderer for line, candle, and overlay data.** A single typed ChartRenderer renders both line/area series and complete OHLC candle series with a separate volume pane, draws overlays for trend lines and flips, DCA buys, cost basis, and margin/liquidation levels, supports touch crosshair and pinch-zoom interaction, and applies decimation for large datasets without changing any already-finalized indicator output. | Verified by a chart-rendering test comparing full-resolution and decimated views of the same fixture and asserting identical finalized trend and overlay output. |
| `FUI-01` | **Responsive five-destination navigation.** The application presents five top-level destinations as a bottom navigation bar on narrow viewports and as a side rail on desktop, keeping the selected route and keyboard focus coherent across layouts. | Verified by a responsive browser test at phone and desktop widths confirming the correct navigation chrome and consistent selection and focus. |
| `FUI-02` | **Instrument groups with distinct data states.** User-defined instrument groups and their Basic/Holdings mode preserve the selected group and mode, and the UI visibly distinguishes loading, genuinely empty, stale, partial, permission-denied, and unavailable results rather than collapsing them into one state. | Verified by a component test driving each data state from a fixture and asserting a distinct, correctly labeled rendering for each. |
| `FUI-03` | **Search resolves by stable identity, not ticker text.** Instrument search and selection key off stable instrument and listing IDs together with venue and quote currency, so a ticker symbol alone never identifies or disambiguates an instrument. | Verified by a test using two identically ticked instruments on different venues and asserting search and detail views keep them distinct by ID. |
| `FUI-04` | **Instrument rows show price, provenance, after-hours value.** Instrument rows and detail views display the current price with session and source provenance, the previous close, price change, a sparkline, a licensed logo or text fallback, and a separately labeled after-hours value when one is supplied. | Verified by a fixture-driven test covering regular, pre-market, post-market, delayed, and missing quotes, asserting each field renders correctly and a missing price is never shown as zero. |
| `FUI-05` | **Detail tabs and range controls expose only supported data.** The instrument detail view offers its tabs, range controls, a line/candle toggle, and a separate volume pane only for the intervals and data types the underlying series actually supports, and explains why an unsupported mode cannot be shown. | Verified by a test driving valid and unsupported timeframe and data-type combinations and asserting unsupported options are hidden or explained rather than silently rendered. |
| `FUI-06` | **Shared ChartRenderer preserves gaps and revisions.** One typed ChartRenderer, shared with the Atlas renderer, draws scalar line/area series and complete OHLC candles, preserves data gaps and bar revisions by ID rather than smoothing over them, and performs no authoritative indicator computation of its own. | Verified by a unit and browser test asserting candle mode only accepts valid OHLC bars, gaps persist, a revised bar replaces the prior one by ID, and no indicator values originate client-side. |
| `FUI-07` | **Chart overlays show strategy version and simulation state.** Available chart overlays include trend lines and flips, DCA buy markers, cost basis, and margin or liquidation levels, and each overlay displays its source strategy version and whether it reflects a simulated result. | Verified by a test comparing full-resolution and decimated chart views on a fixture with a finalized trend flip, DCA buy, cost basis, and simulated margin level, asserting markers align to the correct bars and versions. |
| `FUI-08` | **Performance cards render owner-calculated values verbatim.** Performance and benchmark cards display the fixed-point values calculated by the owning service exactly as returned, together with the return method, currency, source, as-of time, and session, and show an explicit unavailable state rather than a computed or estimated figure. | Verified by a contract-fixture test with multi-currency cash flows, dividends, splits, fees, and a stale valuation, asserting the UI reproduces the owner's decimal-string output with no client-side recomputation. |
| `FUI-09` | **Strategy views cite evidence and never submit orders.** Strategy and recommendation views cite the versioned evidence and scorecard behind each proposal, display an explicit reason when a recommendation abstains, and contain no path that directly submits an order. | Verified by a fixture test covering a calibrated proposal, thin history, warmup, drift, and a missing scorecard, asserting the shown evidence and abstention reason and confirming no order request originates from the panel. |
| `FUI-10` | **DCA and alert views distinguish delivery states.** DCA and alert views present due, missed, failed, replayed, paper-filled, and delivered states as visibly distinct outcomes rather than collapsing them together. | Verified by a fixture test exercising each state, including a duplicated event ID and a channel retry, asserting the states and receipts remain distinct and a paper fill is never shown as a live fill. |
| `FUI-11` | **CSV import preview with idempotent receipt.** CSV import previews the column mapping and row validation errors before committing, reports a source digest and a stable receipt, returns the same logical receipt on a repeated import of the same file, and displays post-import holdings from the owning service's response rather than client-side computation. | Verified by a CSV fixture test with mapped and unmapped columns, a malformed row, and a duplicate digest, asserting preview counts, idempotent receipts, and owner-sourced holdings. |
| `FUI-12` | **Offline PWA shell marks cached data stale.** The installed PWA shell continues to display previously cached financial facts while offline, but marks them stale and disables any action that would imply current market, account, or order state. | Verified by an offline test loading a previously valid finance view without network access and asserting cached values are labeled stale and current-data actions are unavailable. |
| `FUI-13` | **Charts and controls meet accessibility requirements.** Every chart and interactive control operates by keyboard, provides a screen-reader-accessible summary, remains usable at 200% zoom, honors reduced-motion preference, and conveys state through text or icon labels rather than color alone. | Verified by an accessibility review combining keyboard-only operation, screen-reader inspection, 200% zoom, reduced-motion, and high-contrast checks against each chart and control. |
| `FIN-UI-R003` | **GraphOS Markets app with scanner, search, and layered chart.** A GraphOS-hosted Markets application provides a market overview, a scanner with filters, symbol search, and a layered chart view, reusing the shared Atlas OHLC ChartRenderer and the epistemic-graph engine's large-dataset decimation, and exposes its market actions as WebMCP tools. | Verified by an integration test driving the scanner, search, and chart views against fixture market data and confirming the WebMCP tool calls return the expected results. |
