# WEBUI-APPS requirements

| ID | Requirement | Verification |
|---|---|---|
| `APP-01` | **Browser identity consistently reads GraphOS across titles and assets.** Agent-webui's page titles, metadata and web manifest present the GraphOS product identity. Generated assets, theme tokens, UI copy and the published Pages site present the same identity. | Asset regeneration, a rendered snapshot test and the Pages build confirm consistent branding. |
| `APP-02` | **Package, import and environment naming stay on the component identity.** Package and import names remain `agent-webui` and `agent_webui`. Npm metadata, release images, WebMCP identifiers, skills, browser storage, consent keys and environment variable names stay unchanged. Only user-visible strings carry the Graph OS brand. Operator decision 2026-10-09: only front-end-facing items are renamed to Graph OS; agent-webui stays the component name. | Build and wheel tests confirm the component identifiers are unchanged while user-visible strings read Graph OS. |
| `APP-03` | **AppSurface contract declares each app's route, capability and client.** Agent-webui exposes Apps as a single section in nav-registry.ts, where each app declares its route, required capability, typed service client, WebMCP page and optional Atlas renderer through one AppSurface contract. | Contract tests and a route-census test confirm every registered app conforms to the AppSurface shape. |
| `APP-04` | **Contributed app descriptors cannot escalate privilege beyond the contract.** Native apps and validated package-contributed apps resolve to the same AppSurface shape. Untrusted or malformed descriptors cannot register executable code or arbitrary URLs. They cannot grant capabilities beyond the contract. | Tests that submit invalid descriptors and denied capabilities confirm they are rejected. |
| `APP-05` | **Markets consumes the AppSurface contract without shell-side duplication.** Markets is the first app to consume AppSurface. The browser shell must not duplicate its scanner, chart or gateway wiring. | A first-consumer integration test confirms Markets runs through the shared contract alone. |
| `APP-06` | **No browser-state migration is required by the rebrand.** Because storage and consent keys keep their component names, existing browser state and granted permissions stay valid. Any future key change must expire or migrate them with explicit renewed consent. Operator decision 2026-10-09: only front-end-facing items are renamed to Graph OS. Agent-webui stays the component name. | Browser test confirms existing consent and storage survive the user-visible rebrand. |
| `APP-07` | **App navigation supports accessibility and layout states across devices.** Navigation between apps in agent-webui works with keyboard, touch and reduced-motion input across mobile and desktop layouts. Each app surface presents explicit loading, unavailable and denied states. | An end-to-end accessibility test suite confirms these interaction modes and states. |
| `WEBUI-APPS-R001` | **Apps information-architecture section and AppSurface contract.** Agent-webui introduces an Apps section in its navigation information architecture and a reusable AppSurface contract that binds each app's route, capability, typed client, WebMCP page and optional Atlas renderer to the existing shell. | Contract and route-census tests confirm the shared shell binds every declared app surface correctly. |
| `WEBUI-APPS-R002` | **Graph OS brand layer covers user-visible strings.** Page titles, metadata and the web manifest name and short name must present the Graph OS brand. The Open Graph card, UI copy and user-facing documentation headings must present the Graph OS brand. Operator decision 2026-10-09: only front-end-facing items are renamed to Graph OS; agent-webui stays the component name. | A rendered snapshot test and asset checks confirm user-visible strings read Graph OS. |
| `WEBUI-APPS-R003` | **Repository, package and runtime identifiers are not renamed.** The repository, distribution, Python import path and npm package keep the agent-webui identity. The WebMCP identifiers, skills, browser storage keys, consent version, environment variables and release image keep it too. Operator decision 2026-10-09: only front-end-facing items are renamed to Graph OS; agent-webui stays the component name. | Build and packaging tests confirm the identifiers are unchanged. |
